# Omarchy YubiKey 0.6.0

This release integrates reviewed PRs #19–#23, #25, #27, #29 and #31 and resolves
issues #24, #26, #28 and #30.

## Language selection

The setup window now loads any available control catalog, including the new
Brazilian Portuguese translation, with base-language and English fallback.
Previously only German was loaded. The combined catalog includes the new SSH
and OpenPGP actions in English, German and Brazilian Portuguese.

Lock and Polkit now use one resolver for text, digits and direction. Previously
the native translation loader could overlay its English catalog on a translated
locale fallback. Qualified local imports also prevent Omarchy's Commons type
from shadowing the bundled translation component.

Automatic selection follows the account's Setup > Language file, then
LC_ALL, LC_MESSAGES, LANGUAGE and LANG. Explicit helper/language overrides win.
Live account-language changes are watched. English remains correct if there is
no selection and the message locale is C/C.UTF-8. Other setup-window languages
continue to fall back to English; the standalone catalogs cover 50 languages.

## Key management

- Create resident SSH keys from a terminal wizard with a random user ID and PIN
  plus touch required by default. Validate names/comments before creating a
  credential; never overwrite existing local files.
- Show a bounded public user label next to each SSH application's name. This
  distinguishes keys without exposing filenames, credential handles or secrets.
- Keep **Remove copy** separate from **Delete from security key**. Permanent
  deletion requires the copy's exact credential ID, a warning and a typed
  confirmation. Replaced credentials and keys on another device are refused.
  Review Git-host changes before deletion, with no later cancellation prompt.
- Show **Update key** once an OpenPGP key is imported; highlight missing or
  unhealthy keys while keeping removal a separate action.

## Dependencies and security

HKDF 0.13 and SHA-2 0.11 must migrate together. Their separate bot updates failed
because their digest traits were incompatible. The v1 encrypted-store fixture
still decrypts, while wrong secrets, altered credentials and ciphertext fail.
The cipher's zeroization guard remains enabled.

zbus 6 removes the retired zbus 5 serialization/name dependencies. The helper
keeps its synchronous CLI using the supported `block_on` API and the new variant
types. A private D-Bus test exercises actual Secret Service calls, properties,
unlock success/failure, collection/item operations and session cleanup. No real
session bus or saved keyring is contacted. Item secrets are moved out of reply
maps instead of duplicating the plaintext buffers. OpenSSL updates to 0.10.82.
The current RustSec audit reports no vulnerabilities, unsound/yanked crates or
maintenance notices for the release lockfile; no advisories are suppressed.

## Versions and updating

- Suite/setup: **0.6.0**.
- Standalone lock and Polkit: **0.3.1** each, exported from suite **v0.6.0**.
- Rust helper: **0.2.1**. Rebuild an installed helper to deploy the Rust changes.

```sh
omarchy plugin update yubikey.setup
```

For independently installed plugins, update `yubikey.lock` and `yubikey.polkit`
as well. Downloads include exact source, standalone plugin archives and
SHA256SUMS. They contain no prebuilt executables or enrollment data.

## Verification and limits

Validation includes 136 Python tests, 17 JavaScript tests, 10 Rust tests, a release
build, the real dynamic-zlib build-output regression, formatting, publication and
secret scans, catalog consistency and shell syntax checks. Eight native setup UI
runs cover English, German, Brazilian Portuguese and Arabic at 1280 and 640 px.
Six native language scenarios cover locale fallback, regional codes, live account
changes, a custom language file, explicit override and unsafe-code fallback.
Local tests run without external networking, hardware or the user's home/session
services, with resource limits and disposable scratch storage.

This is focused source/integration verification. Fresh physical-key enrollment,
permanent hardware deletion, PAM/lock recovery and LUKS boot qualification were
not performed. Authentication defaults and credential formats are unchanged.
