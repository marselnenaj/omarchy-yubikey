# Omarchy YubiKey 0.6.1

This patch addresses [Greptile's changed-copy review finding on PR #32](https://github.com/marselnenaj/omarchy-yubikey/pull/32#discussion_r4504241649).

When another SSH tool changed the selected local key copy during the typed
permanent-deletion confirmation, 0.6.0 checked that change only after deleting
the original hardware credential. The check now runs after the typed
confirmation and immediately before invoking `fido2-token -D`. A changed,
missing or symlinked copy stops the operation before that irreversible command
or any managed SSH configuration changes. The existing later cleanup checks
are retained. This does not make filesystem changes and a hardware operation
one atomic transaction.

A regression test exercises changes to the private handle, public file and
complete pair, a removed handle and a symlink replacement during confirmation.
All five cases failed against 0.6.0 by reaching the mocked deletion command;
all now prove that no hardware deletion or configuration write occurs and that
the replacement files remain untouched. The full Python suite has 137 tests.
CI also checks the existing JavaScript/Rust suites, catalogs, publication
content, build-output regression and secret scans. Hardware deletion was not
performed during testing.

Suite/setup is **0.6.1**. Lock/Polkit remain **0.3.1**, published from suite
v0.6.0, and the helper remains **0.2.1**. Their code and dependencies are
unchanged. The other Greptile finding, outdated README version numbers, was
already corrected before the 0.6.0 release.

```sh
omarchy plugin update yubikey.setup
```

Downloads contain the exact tagged source and SHA256SUMS. Existing
[0.6.0 features and qualification limits](0.6.0.md) still apply.
